# 员工连续性：四层状态与迁移检查

本文整理实际迁移中发现的边界，不提供一键修改账号的脚本。

## 四层状态

| 层 | 需要核对 | 常见误判 |
| --- | --- | --- |
| 身份 | 原 agent ID、归属与执行位置 | 新建同名 Bot 就算恢复原员工 |
| 历史 | 平台可见聊天、本地会话、文件和记忆 | 复制可见文本就等于恢复隐藏 checkpoint |
| 路由 | 客户端进程中的 roster/harness、Box 收件与平台会话 | 服务端已改配置，客户端一定会刷新 |
| 调度 | 每项任务唯一的执行方、启停状态、时间区、执行收据 | 两边同时开着能增加可靠性 |

更换推理供应商只改变其中一部分。客户端仍可能把消息送到平台；一个未刷新的客户端进程也可能继续使用旧路由。

## 建议顺序

1. 只读盘点原身份、当前路由、可见历史和任务。记录每个来源及采集时间，备份本地状态。
2. 保留原 ID。确认本地已有正确资料和会话；不要为了“恢复”批量创建同名身份。
3. 对分叉的历史做带来源和时间的只读交接。旧消息作为历史材料，不能当作重新授权或新任务自动执行。
4. 单独验证客户端到 Box 的收件路径，必要时完整重启客户端后重新获取 roster。
5. 将每项定时任务明确交给一个调度方，核对原启停状态、时区和触发类型。停机前时间槽不补跑。
6. 用无副作用消息完成真实客户端往返，再单独验收定时任务；保留时间与脱敏收据。

## 证据的含义

- HTTP 200 只能证明某次接口调用成功，不能证明用户正在看的会话收到了它。
- 可见历史归档和本地交接能够补充上下文，但不恢复平台隐藏的内部状态。
- 模型说“已经恢复”不是配置、路由或任务状态的证据。
- 原身份、原文件、可见历史和隐藏平台状态应分别描述保留范围，不能统称“无损”。

alpha.5 候选的 [可选桌面路由工具](../experimental/client-routing/README.md) 支持明确校验的 Windows `0.57.1` / `0.66.0` 结构：按 Electron profile 保存已确认本地归属、失败重试与重连、生成候选并校验 ASAR/EXE。`0.66.0` 适配严格校验原生工厂摘要和接线，保留原生 automation 契约；不会改变创建员工的偏好、服务端权限或功能开关。未知版本或源结构拒绝，工具不会自动部署或决定谁应当迁移。

本机真实 `0.66.0` 包的候选生成与验证覆盖 582 个 packed 条目，两个改写 CJS 的 `node --check` 通过；关闭路由 opt-in 时，原生工厂与适配实现的 10,000 步差分结果一致。这些是静态与运行时逻辑对照证据，尚未认证公开 alpha.5 构建的真实登录、发送、历史、重连或模型往返。健康检查验证完整接线且返回 `runtimeVerified: false`；旧 profile 状态文件不是当前进程的运行收据。

官方 Linux `0.66.0` 客户端的代理、系统 CA 和加密钱包诊断见 [Linux 客户端指南](LINUX-CLIENT.md)。其真实登录及当前已解锁桌面会话内重开通过，只说明官方客户端访问与登录保持；不代表 Linux 桌面路由补丁支持，也不能替代上述迁移验收。

[名单校验核心](../experimental/ownership/README.md) 提供格式检查和最后有效状态保留，可由接入方使用；没有有效初始名单时必须停止归属决策。该模块未由默认安装器注入。

身份切换、隐藏状态迁移和生产任务导入仍未自动化。保存已有归属与主动迁移身份是不同的操作，应分别审核和验收。
