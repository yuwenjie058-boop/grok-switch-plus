# 代码结构与维护原则

PLUS 保留单文件发行，源码按职责维护。构建只负责组合代码和语法校验，运行时接口继续兼容现有配置。alpha.4 的整理围绕已经出现的故障展开。

## 核心模块

| 模块 | 调用方需要知道 | 内部负责 |
| --- | --- | --- |
| `src/protocols/` | 请求和流事件合同 | 各供应商协议、参数交付和工具历史转换 |
| `src/ctx-compact.cjs` | 消息、配置和结果统计；存储不确定错误必须阻止请求 | 原文恢复、记录形态选择、首次折叠、账本提交与重放 |
| `src/maintenance.cjs` / `src/watchdog.cjs` | 维护操作和守护状态 | 写入竞争、快照校验、备份、重启门禁与运行收据 |
| `experimental/client-routing/` | 明确的客户端/账户目录，候选生成与检查 | ASAR 完整性、版本适配、每账户路由记录和重连 |
| `experimental/ownership/` | `has`、`refresh`、`status`；冷启动失败须停止归属决策 | 名单格式校验、读取间隔、时钟回拨和最后有效快照 |

## 这轮简化了什么

上下文模块用同一个内部形态选择函数处理文本和对象结果。调用顺序是先读已有记录，再决定是否创建新折叠；配置变化不再把历史记录挡在筛选器外。保留账本提交和回滚流程，使修复与存储可靠性分开维护。

客户端工具把 ASAR 的解析和完整性规则集中到一个模块。生成器、验证器和检查器共享规则；客户端版本适配使用明确锚点，和文件读写分离。桌面补丁中的路由状态保持按账户隔离，计时器与持久化恢复由该状态实现负责，调用方不维护另一份名单。

名单核心只回答已验证的归属，不修改服务器或账户配置。文件读取与时间来源可替换，测试可直接注入故障。健康元数据不包含名单、文件路径或异常原文。

## 后续改动的约束

- 先在公开源码和合成输入上复现，再增加改变后的行为测试。
- 对同一规则共享实现；只有实际不同的依赖才引入可替换接口。
- 不为短小函数增加只转发调用的类或框架，不因整理源码而改用户接口。
- 生成物从源码重建。已知版本也要核对实际内容，版本标签不能代替结构和完整性验证。
- 分别声明静态检查、故障测试、真实运行验收的证据；未接入默认安装器的工具保持独立。

默认安装器不自动修改桌面、启用实验归属策略或导入任务。工具可以复用，不等于所有客户端版本都兼容。
