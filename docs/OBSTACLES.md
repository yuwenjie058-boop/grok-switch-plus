# 从“能切模型”到持续可用：阻碍、解法与证据

本文对比的是本项目采用的旧 grok-bot-switch 基线与后续运行需求，基线为 `c612786ef8ec5e70c67fc691fea85cee1f06e724`。它不是针对最新上游的缺陷清单；部分问题来自宿主或客户端变化，不能归因于上游作者。我们希望公开的是别人能复用的工程经验和实现。

## 1. 工具能调用，但长任务无法连续执行

**现象：** 连续查询任务进度或重复截图可能被视为失败循环；并行工具的开始事件先到，上一项参数还未完整交付。

**处理：** 以工具结果区分成功重复和连续失败，保留失败熔断；流式工具事件按宿主需要的参数交付顺序输出，不把下一项工具开始当作上一项参数完成。

**实现与证据：** [协议转换器](../src/protocols/)、[runtime 回归](../tests/runtime.test.mjs) 覆盖成功轮询、重复截图、连续失败以及分块交错的工具参数。

**边界：** 这使合法执行可以继续，不证明任务在业务上已经完成，也不取消失败保护。

## 2. 同一份历史，在不同协议中并不等价

**现象：** 工具返回的截图、不同来源的推理内容和文件附件，不一定能直接表示为目标协议的消息；图片被放错顺序也可能改变模型理解。

**处理：** 按协议组织工具结果和图片；对目标协议不能安全回放的历史做明确降级，不伪造有签名的推理状态。

**实现与证据：** [图片顺序测试](../tests/chat-tool-image-order.test.mjs)、[三协议降级测试](../tests/protocol-parity-tool-degradation.test.mjs)、[协议样例](../tests/fixtures/protocols/)。基础三协议能力来自上游，Plus 在其上补充修复与覆盖。

**边界：** 降级可能损失信息，不能称为跨模型“无损记忆迁移”。

## 3. 长输出占满上下文，反复裁剪又改变历史

**现象：** 大型终端输出和工具对象持续进入请求。只处理字符串会漏掉宿主解析后的对象结果；每次重新裁剪已发送内容，会让历史形态不稳定。

**处理：** v4.1 在结果首次发送时决定折叠形态，保留原文与持久化账本；对象采用稳定身份，后续请求复用既有形态。写入失败时放弃新折叠；dry-run 与 apply 尽量保持相同的可处理性判定。

**实现与证据：** [ctx-compact](../src/ctx-compact.cjs)、[v4.1 回归](../tests/ctx-compact-v41.test.mjs)、[存储故障测试](../tests/ctx-storage-failure.test.mjs)、[对象与重放测试](../tests/ctx-compact-v4.test.mjs)。

**边界：** 默认关闭。保留首尾无法保证保留中间的所有语义；原文需要可追溯。前缀稳定是工程目标，实际 token 费用和供应商缓存命中率需要独立测量，本文不承诺节省百分比。

alpha.2 提供 [可直接运行的对照演示](DEMO.md)，并补齐账本文件刷盘、Linux 目录刷盘、竞争写入检查和同批次容量淘汰保护。有限账本与异常情况下的重放边界见 [可靠性说明](RELIABILITY.md)。

## 4. 供应商容量和宿主摘要机制脱节

**现象：** 供应商能接收长上下文，不代表宿主知道其容量。只更换模型名无法保证宿主采用合适的摘要阈值。

**处理：** 使用显式 `contextWindowTokens`，通过完成事件和 usage 中的 `extendedUsage.maxTokens` 传递给宿主；CLI/UI 保留该字段。

**实现与证据：** [runtime](../src/runtime.cjs)、[协议回归](../tests/protocols.test.mjs) 与 [CLI 回归](../tests/cli.test.mjs)；字段由部署者核实，不能复制其他模型的容量。

**边界：** 容量元数据、宿主摘要和工具输出裁剪是三件事。上报正确容量不等于立即触发摘要，也不等于已完成长期压缩验收。

## 5. 更新后补丁消失，或者磁盘和运行进程不一致

**现象：** 官方更新替换宿主，补丁不再生效；重新写好文件后，旧进程可能仍运行旧代码。仅凭文件存在或 PID 存在无法确定恢复。

**处理：** 用维护锁、稳定快照和结构检查控制写入；空闲时备份并请求重启；运行时收据记录实际加载版本与哈希；验证失败锁定，避免无限重启或静默切模型。

**实现与证据：** [maintenance](../src/maintenance.cjs)、[watchdog](../src/watchdog.cjs)、[守护回归](../tests/watchdog.test.mjs)、[持久性测试](../tests/watchdog-durability.test.mjs)、[并发快照测试](../tests/watchdog-loop-and-snapshot.test.mjs)。

**边界：** 未知宿主结构必须停下分析，不能承诺兼容未来更新。观察进程的启动管理仍由部署环境负责；收据和实际请求都要核对。

## 6. 会话和定时任务迁移后，模型通了但员工仍不工作

**现象：** 本地供应商请求成功，用户发的消息却进入平台会话；可见历史分叉；两个调度方同时存在可能重复执行。

**处理：** 将身份、历史、客户端路由、调度分别验收。保留原 ID，对可见历史做标注来源的只读交接，刷新客户端路由；每项任务只有一个执行方，使用持久化时间槽收据，不补跑历史任务。

**公开成果与证据：** [迁移流程](MIGRATION.md)、[实验调度核心](../experimental/local-cron/README.md) 和 [13 项合成调度测试](../experimental/local-cron/local-cron.test.cjs)。真实部署观察用于形成流程，私有会话和任务不作为公开测试材料。

**边界：** 首发没有通用身份迁移器、客户端补丁安装器或隐藏平台 checkpoint 导出。调度模块还需要宿主接口和云端排重门禁。已经在特定环境克服的障碍，与已产品化的通用工具，需要分开陈述。

## 如何把经验进一步做通用

当前已做到：核心测试无需账号；协议与供应商参数分离；示例不绑定员工、模型容量或私有网络；实验调度采用依赖注入；运行路径可由已有环境变量覆盖。

下一步按可验证程度推进：

1. 在已有 [兼容矩阵与只读结构预检](COMPATIBILITY.md) 基础上，积累真实宿主版本的验收记录。
2. 把身份、历史和路由盘点做成只读预检，输出差异与计划。
3. 为迁移写入增加显式映射、逐项收据和可逆步骤，再提供自动化入口。
4. 收集不同模型/宿主的脱敏回归，持续检查缓存、长期任务与恢复行为。

这些是后续工作方向，尚未实现的内容不列为现成功能。
