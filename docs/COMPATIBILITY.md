# 兼容性与证据等级

适用候选：`0.1.0-alpha.5`（预发布）。这里区分“开发环境测试”“宿主静态结构检查”和“真实客户端往返”，避免把一个层面的通过当成全部兼容。CI 矩阵描述工作流配置，不表示尚未运行的远端任务已经通过。

| 环境 / 合同 | 支持范围 | 验证方式 |
| --- | --- | --- |
| Windows + Node.js 20、22、24 | 构建、离线演示、预检、合成回归 | 核心 GitHub Actions 矩阵；不代表默认安装器支持桌面端安装 |
| Linux + Node.js 20、22、24 | 同上，额外覆盖目录刷盘失败 | 核心 GitHub Actions 矩阵 |
| 上游 0.8.5 → PLUS alpha.3 | 合成宿主上的更新路径 | 使用上游 `2005450` 的实际公开构建安装后，PLUS 预检、更新成功，供应商配置和原始宿主备份保持不变；不等于真实宿主认证 |
| Linux Box，包含唯一推理工厂及所需 Prompt 接口 | 可能满足基础注入合同 | `preflight` 检查当前文件，不按版本名称猜测 |
| 含 `FileTranscriptMirror` 的宿主 | 必须满足特定 journal 比较、UserMessage 时间字段及解码接口 | 合成 journal 回归 + 当前文件预检 |
| 含 `createSendMessageTool2` 的宿主 | 必须满足三个 terminal hook 锚点 | 合成 hook 回归 + 当前文件预检 |
| Windows 桌面客户端 / 平台 Temporal 会话 | 本仓库安装器不负责迁移 | 参见迁移设计；不能靠一次 preflight 宣称兼容 |
| 可选桌面路由工具，Windows 客户端 0.57.1 / 0.66.0 | 按版本适配精确结构并验证完整接线；未知版本或源结构拒绝 | 合成 ASAR、故障注入；工具 CI 为 Node 20/24 × Python 3.10/3.12 × Linux/Windows；不自动部署 |
| 官方 Linux 客户端 0.66.0 | 代理、系统 CA、安全存储诊断；不是 PLUS 桌面适配器 | 正确账号/员工列表及同一已解锁桌面会话内正常重开通过；见 [Linux 指南](LINUX-CLIENT.md) |
| 名单校验核心 | 显式确认名单、读取失败和格式错误的恢复规则 | 核心 Node 20/22/24 × Linux/Windows 测试矩阵；合成与真实临时文件测试，未接入默认安装器 |
| 其他 Node 版本、未知宿主结构、未来官方更新 | 未认证 | 需新增复现和版本适配 |

**公开 alpha.5 完整构建的真实宿主版本验收列表目前为空。** 历史私有部署修复、官方客户端登录成功和公开工具的合成测试，都不能等同于整个公开发行版的真实运行认证。桌面客户端版本号也不能替代 Box 内的宿主版本与文件哈希。

## 0.66.0 候选适配证据

`0.66.0` 适配器严格校验操作方提供的原生 roster 工厂 SHA256，以及所需的唯一源码锚点；版本号匹配本身不够。原生 automation 返回值与状态语义保持不变，未修改员工创建偏好、权限或功能开关。保留 `0.57.1` 独立适配器，不用新版本字符串套用旧结构。

| 已执行检查 | 结果与限制 |
| --- | --- |
| 本机真实 Windows 0.66.0 安装包 stage + verify | 通过，覆盖 582 个 packed 条目、候选 ASAR/EXE 一致性；未部署，不证明供应商签名或真实运行 |
| 两个改写后的 CJS 执行 `node --check` | 通过，只验证语法，不启动官方应用 |
| opt-in 关闭时原生工厂与适配实现 10,000 步差分 | 一致，覆盖该对照输入中的原生路由与 automation 契约；不是账号或服务端认证 |
| 完整接线健康检测 | 按版本检查接线与嵌入运行时，不能仅凭补丁标记判健康；`runtimeVerified: false` |
| 公开候选真实登录、发送/回复、历史、重连、模型往返 | 未验收；需在明确授权的测试会话中另行完成 |

上述本机安装包只用于本地验证，不随仓库分发。官方 Linux 登录与同会话重开的通过记录属于客户端访问层；未验证整机重启、无人值守解锁，也不构成 PLUS Linux 桌面安装支持或完整 `0.66.0` 认证。

## 先判断当前文件

无账号体验：

```sh
npm run preflight -- examples/synthetic-host.cjs --json
```

分析你有权访问的宿主文件副本：

```sh
node dist/grok-switch.cjs preflight /absolute/path/to/host-main.cjs --json
```

在目标 Linux Box 上，可省略路径，使用默认宿主路径或 `GROK_SWITCH_HOST`。它只读取宿主和自身程序，在内存中生成候选并通过 stdin 检查语法。不会执行宿主、读取供应商配置、创建备份、调用 API、更新守护或申请重启。

- 退出码 **0**：静态结构通过，`eligible: true`，仍须实际运行验收。
- 退出码 **2**：已完成预检但被阻断，查看 `checks` 中失败的阶段。
- 退出码 **1**：命令参数等其他 CLI 错误。
- `runtimeVerified` 始终为 `false`，预检没有做真实运行验证。

失败阶段：`host_snapshot`（缺失、非普通文件或读取中变化）、`patch_integrity`（已有补丁不完整）、`host_contract`（必要结构不匹配）、`candidate_syntax`（候选语法无效或检查超时）。为防止泄露源码，JSON 不输出宿主内容或解析器引用的源代码。

一次预检是某个时刻的快照。官方更新后需要重跑，安装器也会在写入前再次检查。它不检测供应商额度、消息路由、活跃任务、所有自定义补丁冲突或业务任务结果。

## 如何增加真实兼容记录

提交 Plus 版本、Node/OS、官方宿主版本（若能读取）、宿主文件 SHA256、预检结果，以及经过脱敏的真实客户端往返和工具调用结果。声明是否测试恢复与更新路径。不要上传原宿主、配置、对话或私有网络信息。

维护者复现后再增加“真实运行已验证”记录。单独报告安装命令成功或 HTTP 200 不足以认证。
